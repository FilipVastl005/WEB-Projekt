Hardware Foundations

Core Electronics, Power Physics & Sensors

Mateo hardware is engineered for multi-year unattended operation in harsh atmospheric environments. Below is the master component specification shared across all station variants.

Compute Core

ESP32 MCU Family

We use standard Espressif SOCs: ESP32-C6 for Wi-Fi 6 / TWT, ESP32-C3 for Sub-GHz LoRa edge masts, and ESP32-S3 for Home Deck and Solar Hub servers.

  • ESP32-C6: Wi-Fi 6 + IEEE 802.15.4
  • ESP32-C3: RISC-V 160MHz Low Power
  • ESP32-S3: Dual-Core + Octal PSRAM
Power Storage

LiFePO₄ & TP5000 Solar

Single-cell Lithium Iron Phosphate (LiFePO₄ 3.2V / 3.6V max) chemistry prevents thermal runaway during high ambient heat and survives over 2,000 charge cycles down to -20°C.

  • Cell Type: 3.2V 18650 / 26650 LiFePO₄
  • Charger IC: TP5000 (3.6V Cutoff)
  • Cutoff Guard: < 2.9V Deep Sleep
Sensors

Atmospheric Payload

Precision Bosch BME280 handles barometric pressure, temperature, and relative humidity over I2C. Optional MQ-135 handles air quality index (AQI) with MOSFET power gating.

  • Pressure: BME280 (300-1100 hPa)
  • Temp/Hum: ±0.5°C / ±3% RH
  • AQI Isolation: MOSFET Heater Gating
Thermal Physics Requirement (Preventing MCU Self-Heating) On-board ESP32 RF transmitters (Wi-Fi/LoRa) generate momentary thermal spikes up to +4°C inside tiny enclosures. All Mateo firmware is hardcoded to sample the BME280 I2C bus immediately upon waking before initializing RF radios. Additionally, high-draw heaters like the MQ-135 (150mA draw) are powered strictly via an N-Channel MOSFET gate only when 5V USB/Solar auxiliary power is actively detected.
Deployment Architectures

Deep-Dive into the 3 Station Topologies

Each topology is specifically designed for a distinct physical environment, balancing network bandwidth, battery survival, and infrastructure independence.

Topology 1

Standalone Urban Wi-Fi 6 Station

Urban rooftops, apartment balconies, smart city poles

ESP32-C6 SOC Wi-Fi 6 Target Wake Time (TWT)

How It Works & Power Dynamics

Topology 1 connects directly to residential or municipal 2.4GHz Wi-Fi networks. Instead of remaining connected constantly (which drains 80mA+), the ESP32-C6 negotiates a Target Wake Time (TWT) schedule with the router.

The device stays in a deep sleep state drawing just 7µA. Every 10 minutes, the internal RTC wakes the MCU, samples the BME280 sensor within 15ms, transmits a TLS/HMAC-signed JSON payload to the Mateo cloud API, and immediately returns to sleep.

• Deep Sleep Current: 7 µA
• TX Burst Window: 15 ms @ 180 mA
• Average Power Draw: ~0.042 mW
• Expected Battery Life (No Sun): 180+ Days on 3000mAh LiFePO₄

Topology 2

Sub-GHz Wireless + Home Deck Hub

Suburban properties, community gardens, local homesteads

Node A (Outdoor Mast) + Node B (Indoor Hub) 868 MHz / 915 MHz LoRa Slotted TDMA

Two-Node Architecture

  • Node A (Outdoor Mast Sensor) ESP32-C3 + SX1262 LoRa module mounted on an elevated weather mast up to 2km away from the house. Runs strictly on solar power. Sleeps continuously using RTC timers and wakes every 5 minutes to listen for Node B's sync beacon.
  • Node B (Indoor Home Deck Hub) ESP32-S3 hub plugged into home mains power with a local TFT screen. Broadcasts a beacon, receives Node A packets, logs CSV to microSD, auto-discovers with Home Assistant, and syncs data to the cloud.

Offline Resilience & File Integrity

If home internet disconnects, Node B serves a full local web interface at http://homedeck.local directly over local Wi-Fi.

All telemetry is appended to an onboard microSD card in raw CSV format. The firmware implements a pre-allocated FAT32 block system to prevent MCU write-blocking or filesystem corruption if power is pulled during disk activity.

Topology 3

Autonomous Off-Grid Mesh Kiosk

Off-grid villages, remote agricultural valleys, disaster response zones

Peer-to-Peer Sub-GHz Mesh Delay-Tolerant Networking (DTN)

Zero-Grid Mesh Routing & Captive Portal

In regions completely lacking cellular towers or grid electricity, multiple Node A sensor units form a peer-to-peer LoRa mesh using CSMA/CA collision avoidance.

Telemetry routes across hops to a central Community Solar Kiosk (ESP32-S3 or Raspberry Pi Zero 2W). The kiosk hosts an open Wi-Fi Access Point (`http://community.weather`). Local villagers can connect using any mobile browser to inspect soil moisture, frost warnings, and local rainfall without needing mobile data.

Delay-Tolerant "Data Mule" Synchronization (DTN) When visiting aid workers or agricultural inspectors pass near the Community Solar Hub, their phone automatically pulls encrypted historical CSV batches via the REST endpoint /api/v1/export/sync. When the device returns to cellular range, it silently pushes the batch to the Mateo cloud.

Mechanical Engineering

3D Printable Louvered Stevenson Screen

Exposing sensors to direct sunlight causes solar radiation errors exceeding +10°C. Mateo provides open-source STL files for a modular, louvered radiation shield.

01

Filament Selection

MUST use ASA or PETG filament in Signal White (RAL 9003). Standard PLA deforms and warps under UV rays above 45°C. White color maximizes solar reflectance (>85%).

02

Dual Chamber Isolation

The enclosure features an upper sealed IP65 compartment for the lithium battery/PCB and an isolated lower double-louvered chamber for the BME280 sensor to allow free airflow without radiant heating.

03

Mesh & Gasket Seals

Incorporate fine stainless-steel mesh (0.4mm wire gap) over louver intakes to prevent spiders and nesting insects from blocking sensors. Silicone O-rings seal the electronics box.

Deployment Manual

Step-by-Step Station Setup & Provisioning

Follow this workflow to flash firmware, authenticate keys, and pair new weather hardware with the Mateo Zero-Trust network.

1

Flash Bare-Metal Firmware

Connect your ESP32 board via USB-C. Clone the Mateo open-source repository and compile using PlatformIO or ESP-IDF v5.1+.

pio run -e esp32-c6-urban --target upload
2

HMAC Key Exchange & Cryptographic Provisioning

On first boot, the station enters AP Provisioning Mode (`Mateo-Setup-XXXX`). Connect via browser to http://192.168.4.1. The station sends a CSR request to `/api/v1/provision` and receives its cryptographically signed HMAC secret key stored in ESP32 NVS flash.

3

Physical Mast Mounting & Leveling

Mount the station on a vertical mast 1.5 to 2.0 meters above ground level over natural grass/soil (avoid black asphalt or metal roofs). Align solar panel south (Northern Hemisphere) or north (Southern Hemisphere) at an angle equal to your local latitude + 15°.

4

SQI Initialization & Public Map Live Validation

Once telemetry begins flowing, the station starts with an initial SQI score of 80%. After 24 hours of clean spatial IDW cross-validation against neighboring stations, it achieves Platinum status (95%+) and appears on the public live vector map.

Maintenance

Troubleshooting & Diagnostics

Quick fixes for common field assembly and network transmission issues.

Status LED Blinks 3 Times Red: Low Voltage Brownout Protection +
The battery voltage has dropped below 2.9V. The ESP32 will enter protective deep sleep for 4 hours to prevent cell degradation. Check solar panel connections or clean dust off the solar glass face.
BME280 Reading Static Temperature or -999 Error +
Check I2C SDA/SCL pull-up resistors (4.7kΩ to 3.3V). Ensure I2C address jumper on BME280 module is set correctly (`0x76` or `0x77`).
Home Deck SD Card Write Error (Node B) +
Re-format the microSD card using FAT32 with 32KB allocation unit size. Firmware automatically executes chkdsk repair routines on boot if unclean unmounts occur.
